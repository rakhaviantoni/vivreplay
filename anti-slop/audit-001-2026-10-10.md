# UI audit, 2026-10-10

These findings match the areas the product owner requested for this pass.

1. **HIGH, mobile listing detail squeezes content and adds avoidable scroll.** `components/tcg/market-listing-items.tsx` uses a single-column phone layout while `app/vivreplay.css` preserves desktop-scale art, heading, facts, and spacing. This conflicts with R-03: mobile needs a deliberate layout with readable hierarchy, no collisions, and appropriate density.

2. **HIGH, listing selection actions clip their labels on phones.** The mobile rules set fixed-height buttons with `white-space: nowrap`, ellipsis, and hidden overflow. This conflicts with R-03 because users cannot read the actions and tap targets are below the recommended 44px.

3. **MEDIUM, admin opens on a catalog-health workbench instead of an operational overview.** The existing dashboard exposes separate tools but has no sales/customer overview, trend view, or customer management. The initial page also loads the full catalog-health report immediately. This conflicts with R-05's content-driven structure and R-17's requirement that dashboard numbers come from real, scoped data.

The owner explicitly requested all three areas in this pass, so they are the selected findings for implementation.
